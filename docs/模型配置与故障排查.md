# 模型配置与故障排查

页面“模型设置”支持 DeepSeek、Qwen、Kimi、OpenAI、Ollama、LM Studio 与自定义 OpenAI 兼容服务。

配置写入当前用户目录 `.tr-ai-assist/tr-ai-assist.json`。保存后的 API Key 不回传页面；状态接口只返回 `hasApiKey: true/false`。密钥不得放入任务 JSON、源码、日志、截图或参赛包。留空保存会保留已有密钥，只有勾选“清除已保存的密钥”才会删除。

参赛版启动脚本与桌面演示包顶层一键 EXE 启用独立评审模式，改用 `.tr-ai-review/tr-ai-review.json`，不迁移或读取旧目录中的个人模型。评委首次打开时需自行添加有权使用的模型；看到服务商示例字段并不代表已经配置可用模型。开发模式下的 `.tr-ai-assist` 保留给原用户，交付包不会带走其中的密钥。测试连接会调用评委自己配置的服务，可能产生其账户用量。

安全限制：远程 Base URL 必须是 HTTPS；HTTP 仅接受 `localhost`、`127.0.0.1` 或 `[::1]`。地址不得带用户名、密码、查询参数或片段。

排查顺序：

1. 先确认不勾选模型时，确定性评估和固定模板正常。
2. 检查服务商、Base URL 与模型名称是否匹配。
3. 云端模型检查网络与用户自己的额度；本机模型检查服务是否监听对应回环端口。
4. HTTP 状态错误只记录状态码，不记录响应正文或密钥。
5. 请求超时或取消后，旧响应不会覆盖当前任务；可以新建会话重试。

真实模型内容质量与响应速度没有在本次交付中验证，不应把离线测试结果解释为真实模型成绩。
