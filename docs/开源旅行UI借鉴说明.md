# 开源旅行 UI 借鉴说明

## 目标

V5 保留完整 Claw 客户端与既有文旅能力，把原先连续堆叠的业务表单改为对话优先、结果可视、复杂操作按需展开的行程体验。所有参考项目均在 `UI-reference` 中以只读 ZIP 形式审查，没有安装或执行其脚本。

## 采用的设计思想

- AdventureLog：逐日行程卡、地点类型标识、住宿上下文和地图筛选的信息层级。
- TREK：方案摘要、地图与行程双栏联动、预算概览和协作状态的渐进展示。
- TRIP：地点顺序、交通分段标签、地图/列表互相定位的表达方式。

V5 自行实现旅程摘要、方案卡、逐日时间轴、路线拓扑、费用组成、证据有效性和风险摘要。页面只读取既有 `TravelWorkbench` 状态和确定性评估结果；切换方案通过统一状态入口完成，不建立第二套权威数据。

## 明确未采用

- 不复制三个项目的代码、CSS、图标、图片、品牌、演示数据或产品文案。
- 不移植其 React、Angular 或 Svelte 应用框架。
- 不引入账号、社区、旅行足迹统计、云协作、在线预订或付款能力。
- 不把没有坐标的数据绘制成貌似真实的地理地图；当前使用标有“示意路线”的拓扑视图。

## 许可证边界

- AdventureLog：GPLv3，仅 clean-room 借鉴产品交互思想。
- TREK：AGPLv3，仅 clean-room 借鉴产品交互思想。
- TRIP：MIT；当前仍未复制其代码或素材，因此没有新增代码级归属要求。

如以后决定复用任何第三方实现，必须先逐文件完成许可证评估，并同步更新 `THIRD_PARTY_NOTICES.md`、源码版权头和交付清单。

## 后续阶段

真实地图与联网路线属于后续基础工具阶段。届时必须采用可配置提供方、来源与时间标识、超时/取消、最小字段发送和离线降级；外部结果先作为待核实事实，不得自动升级为已确认资料。
