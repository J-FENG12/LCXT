# 旅策协同 4.2.0：开始使用

## 离线演示（推荐先走）

1. 双击根目录 `旅策协同-离线体验.cmd`。
2. 在“咨询问答”选择资源并检索本地事实卡。
3. 在“需求与方案规划”核对日期、人数、预算、天气和兴趣，点击“确定性评估”。
4. 查看“通过已录入条件校验 / 待核实 / 不满足”、已知小计和结构化问题。
5. 可点击“自动组合候选”；结果最多 12 个，均重新通过同一规则核心。
6. 在“资源管理”编辑资源、事实或交通，或原子导入/导出 schema v2 任务 JSON。修改会立即清除旧结果。
7. 离开页面前导出需要保留的任务；工作台默认只存内存。

虚构案例晴天最低完整费用为 A 方案 2130 元，最少步行为 B 方案。C 使用待核实演出事实且存在交通缺口，不进入通过方案推荐。

## 文旅 Agent

1. 双击 `旅策协同文旅Agent.vbs`。
2. “同步服务端评估”不会调用模型。
3. 选择通过方案，勾选已核对，建立绑定任务哈希和方案的服务端确认。
4. 生成服务、营销或产品固定模板无需模型；只有勾选“使用已配置模型”后点击生成才会产生用量。
5. 任务或选定方案变化后必须重新评估与确认。
6. 完成后从 Agent 页面退出，释放本机端口。

如需需求原文整理或模型内容功能，先通过 `旅策协同桌面版.vbs` 配置用户自己的模型。不要把 API Key 写入游客需求、任务 JSON 或截图。

## 数据边界

真实任务应录入结构化资源与事实来源、确认日期和适用期。缺少价格、交通、容量、饮食或无障碍能力时，系统显示待核实而不是自行推断。系统不会联网查询、预订、付款、联系商户、上传或发布。
