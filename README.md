# 旅策协同 Travel.AI 4.2.0

面向景区、酒店、餐饮服务岗位及旅游管理、文化创意、数字媒体专业实训的文旅全场景智能辅助 Skill 系统。4.2.0 用同一份可追溯任务贯穿有据咨询、游玩旅居餐饮规划、服务接待、营销草稿和产品创意。

## 开发预览

双击根目录唯一的 `启动旅策协同.vbs`，打开完整桌面工作台。它使用本机开发配置，包含模型设置、文旅 Agent 和三个 OpenClaw Skill。首次冷启动请等待窗口加载；若没有出现窗口，查看 `logs/launcher.log`。

修改前端、Skill 或桌面运行代码后，先在本目录运行 `npm run build:desktop`，再双击 VBS 查看最新成果。普通源码检查可运行 `npm test`、`npm run test:evaluation` 和 `npm run test:browser`。构建使用现有本地依赖和授权运行输入，不会调用模型。开发期间只维护这一份工作目录和这一个双击入口。

桌面窗口右上角关闭通常缩到托盘，彻底停止请从托盘选择“退出”。独立文旅 Agent 应点击其“退出”入口释放本机端口；测试不同版本前不要同时运行多个同源实例。

桌面冷启动由旅策协同原生窗口宿主管理：第一帧显示“旅策协同 · 正在启动”，完成文旅前端与 Agent 桥加载后再切换到正式窗口，不展示底层授权运行输入的初始标题或图标。派生桌面程序未签名，Windows 可能显示常规安全提醒。

开发入口使用当前 Windows 用户的 `.tr-ai-assist` 配置目录；已有模型和工具配置会按原有权限加载。不要把个人用户目录复制进源码或分享给其他人。

桌面版和本机文旅 Agent 会把当前任务原子保存到 Windows 用户目录 `.tr-ai-assist/tasks/current-task.json`，不会写入项目或交付包。离线 HTML 不访问用户目录，只保存当前页面状态。新安装从非模拟空白任务开始；“云水古城”虚构数据只有点击“载入演示”后才进入当前任务。

“基础工具”与“模型设置”相互独立。搜索、天气、路线和地理坐标工具配置保存于 Windows 用户目录 `.tr-ai-assist/tools/tool-config.json`，默认全部关闭，密钥状态只回传“有/无”。联网搜索可由用户自行配置 Tavily API Key，或连接自建 SearXNG；天气、路线与资源坐标可使用用户自己的高德 Web 服务 API Key。外部调用额度、服务条款和数据可用性由相应账号或实例维护者负责。

SearXNG 接入时，在“基础工具 → 联网搜索”选择“SearXNG 搜索”，局域网可填写明确的私网 IPv4 Base URL（例如 `http://192.168.6.162:8888`），公网只接受 HTTPS 域名；程序固定调用该 Base URL 下的 `/search` JSON API。访问令牌为可选项，只会作为 Bearer 头保存于当前用户目录，不进入源码、状态接口或交付包。不要把 SearXNG 的未加密服务端口直接暴露到公网，应使用带 HTTPS、访问控制与限流的反向代理。

高德接入时，在“基础工具设置”顶部只需填写一次“Web 服务”类型 Key 并点击“保存并启用高德服务”。天气、路线与地理坐标会同时切换到固定官方地址 `https://restapi.amap.com`；程序自动完成行政区 `adcode`、资源地址坐标及路线参数转换。Key 只保存在当前用户目录，按高德要求作为官方 HTTPS 请求的 `key` 查询参数发送，不进入状态接口、审计内容、源码或交付包。天气结果进入待核实候选箱；路线、费用、时长和坐标只展示为核对结果，不自动覆盖正式任务。

在对话中点击“让模型建议公开资料检索”，模型只能在“开放时间、门票、交通/无障碍”主题与当前公开目的地/资源之间选择；页面展示实际检索词后，用户点击确认才会调用搜索服务。真实请求不包含游客原文、个人偏好、事实正文或模型生成的任意 URL；单个任务版本最多 3 次真实搜索，次数记录在用户目录 `.tr-ai-assist/tools/tool-usage.json`。搜索和模拟天气结果先进入 `.tr-ai-assist/tools/observations.json` 候选箱，不会自动修改行程。候选绑定任务 ID、revision 和哈希；任务变化后旧候选不可采纳。用户可忽略候选，或人工采纳为 `unknown` 事实草稿，再自行核实来源与内容。模拟候选不能写入非模拟任务；搜索摘要的 24 小时复核期限不代表网页事实本身的有效期。

## 4.2.0 能力

- 两条参赛主流程：游客咨询与游住餐规划；基于确认方案的文旅营销与产品创意。页面首页可直接进入，不要求普通用户手写 JSON。
- 对话优先的行程视图：保留完整 Claw 客户端；工作台默认显示旅程摘要、方案卡、逐日时间轴、路线示意、预算、证据与风险，复杂编辑器按需展开。
- 对话生成工作台：在主对话选择“文旅需求规划”后直接描述需求；模型先返回字段差异草案，人工点击“应用并生成方案”后，同一任务才进入工作台并由确定性核心评估。
- 模块化对话修改：工作台可把整体需求、住宿、交通区间或具体景点/餐饮/活动带回主对话；模型只能按目标白名单形成绑定 `baseRevision + taskHash` 的提案，确认前不改任务，确认后全量重算派生结果。
- 任务恢复与撤销：本机入口保存当前任务、确定性评估和最多 20 个历史版本；重启后恢复同一任务，撤销最近修改会生成新的 revision，不回写旧版本。损坏存档和旧窗口覆盖均被拒绝。
- 基础工具安全骨架：搜索、天气、路线和坐标采用独立白名单、任务 revision/hash 绑定、单任务调用上限、最多 2 个并发、取消、短期缓存和脱敏审计；Tavily/SearXNG 搜索需用户启用并确认查询，高德只接受固定官方主机并由用户主动运行核对。天气和搜索结果仅为待核实候选，路线与坐标不自动写入任务。远程传输门固定核验后的连接地址并限制重定向、响应大小和超时。
- 候选资料箱：搜索和天气候选保留来源、获取时间、模拟状态和任务版本；采纳由本机服务核对已保存任务，写入的事实保持 `unknown`，不会成为已确认依据。
- 方案联动：切换方案卡会同步更新逐日安排、交通分段、住宿上下文、费用构成和旧工作台选择，不复制或另存一份业务状态。
- 需求核对：自然语言先生成差异草稿，支持人数、预算、到离时段、过敏原与无障碍约束的局部更新；含糊指代先澄清，应用前不修改任务。
- 中文资料维护：可从空白创建景区/酒店/餐饮资源、首条事实卡和交通区间；取消不落数据，被引用记录不能删除。
- schema v2：任务 UUID/版本、逐日时段/餐次、住宿夜、结构化饮食与无障碍需求、事实卡、显式交通、独立住宿和候选方案。
- 确定性规则：证据时效、过敏原/交叉接触、无障碍三态、房型与时段容量、不同年龄门票次数、按人/房晚/固定价格、未知价格、开放/重叠、交通、步行、雨天和预算。
- 推荐语义：只在“通过已录入条件校验”的候选中比较；最低价排除总价不完整方案，轻松方案比较最大单日/总步行，体验方案比较明确兴趣覆盖。
- 咨询：本地关键词与字段加权检索最多 8 张事实卡；显示来源、日期、冲突与模拟标识；可选模型引用只允许本轮 factId。
- 自动组合：按逐日窗口、开放时间、服务时长和显式交通边排程，稳定去重并保留手工方案；截断列出原因，取消/迟到响应不覆盖当前任务，不伪装成最优或无解。
- 状态安全：服务端绑定 `taskHash + selectedPlanId + confirmationId`；预算、资源、事实、交通或方案变化后旧确认和交付资格失效。
- 三类交付：接待执行单、渠道化营销稿、产品创意卡均带确认/方案/事实/引擎/模拟/生成方式元数据；模型调用前可预览公开字段投影，事实正文和游客个人原文默认不外发；草稿可编辑并导出 Markdown、JSON 或打印/PDF。

内置“云水古城”及全部资源均为虚构实训数据。当前工作台路线主视图仍严格依据已录入交通区间生成，并标注为不代表地理比例的示意路线；高德适配器可返回真实坐标、路线距离、预计时长和有限几何，但在 Schema v3 与人工采纳流程完成前不会替换正式交通数据，也尚未加载第三方地图底图。模拟工具不会访问互联网；Tavily/SearXNG 联网搜索与高德天气均只返回待核实资料。系统目前不接铁路、航班、票务、库存或商户系统，不会自动联系、预订、付款、上传或发布。

## 三个 OpenClaw Skill

- **文旅需求规划**（内部标识 `travel-demand-planner`）：需求整理、本地事实咨询、候选生成与确定性规划。
- **文旅服务协同**（内部标识 `travel-service-coordinator`）：当前确认方案的接待日程、核对清单和客服草稿。
- **文旅内容创意**（内部标识 `travel-content-lab`）：营销允许字段投影、可审内容和事实/创意分栏产品方案。

客户端技能列表和 `@` 选择界面使用中文显示名；英文内部标识保持不变，用于兼容 OpenClaw 的目录、配置和调用协议。用户点击中文 Skill 即可调用，无需输入英文标识。

首次规划时，在主对话中选择“文旅需求规划”并发送需求。需求草案必须人工确认后才会生成工作台方案。进入工作台后，可从旅程摘要、住宿卡、交通区间或逐日行程项目点击“在对话中修改”。当前整体需求只开放人数、预算、步行上限、天气偏好和兴趣白名单；住宿支持同类型替换、房间数与入住/离店字段调整；行程项支持同类型资源替换、开始时间修改、跨日移动和删除；交通支持总耗时、步行耗时、计费方式、金额和已录入交通服务绑定。交付材料仍可直接人工编辑，其结构化对话改写在后续阶段。

没有新增重复的第四个通用旅游 Agent。第三方候选 Skill 仅作 clean-room 设计参考，未复制或执行；审查记录在 `.development/plans/第三方Skill参考评估.md`。新行程视图对 AdventureLog、TREK 与 TRIP 进行了只读评估，仅 clean-room 借鉴地图/行程联动、逐日卡片和路线分段的信息组织，未复制代码、素材、品牌或文案，详见 `docs/开源旅行UI借鉴说明.md`。

## 模型与数据

模型设置支持 DeepSeek、Qwen、Kimi、OpenAI、Ollama、LM Studio 和自定义 OpenAI 兼容服务。配置位于 Windows 用户目录 `.tr-ai-assist/tr-ai-assist.json`，不进入项目或发布包。远程地址必须 HTTPS，本机回环可用 HTTP。

评审模式的模型配置路径改为 `.tr-ai-review/tr-ai-review.json`，工具和任务也只写入该独立目录；开发调试模式仍使用上文所述 `.tr-ai-assist`。两个目录均位于当前 Windows 用户目录，不在源码或 ZIP 内。评审模式不会从旧目录迁移密钥。

确定性评估、事实检索、候选组合和固定模板不需要模型。只有用户勾选并点击模型功能才会调用当前配置服务并产生用量。API Key 不进入页面、任务、trace、截图或导出。

## 构建与验证

```powershell
cd "<V5项目目录>"
npm run check:environment
npm run build:app
npm run build:desktop
npm run test:source
npm test
npm run test:evaluation
npm run test:live-dry-run
npm run test:browser
```

`build:desktop` 更新双击入口使用的桌面资源。`build:app` 只构建源码 Web 页面。`test:live-dry-run` 默认真实模型调用为 0；只有显式传入 `--live --budget-tokens N --max-requests N` 才可能调用。

## 材料与责任边界

- `tourism/training/`：三专业实训任务书和量规。
- `tourism/defense/`：架构、原创贡献、8 分钟演示和赛题映射。
- `tourism/赛题符合性审查.md`：基于用户提供赛题文本的诚实自审，不等同主办方验收。

派生桌面程序未签名，不冒充第三方签名或开发团队。底层运行时与第三方组件不宣称原创；当前结果只证明已录入资料和固定测试条件下的行为，真实数据与模型内容质量需另行授权验证。
