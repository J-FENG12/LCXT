# 旅策协同评审讲解稿

本稿对应 `tools/submission-video-segments-review.json` 和评审讲解版视频。开场从景区前台的真实工作问题讲起，不朗读赛题编号或产品全称。赛题编号保留在 PPT 页脚，供评委核对。请用自己的语速和日常措辞录制人声；自动生成的视频配音仅是审片和无录音条件时的备用版。

## 讲解主线

1. 前台接到一家四口的两日游需求：孩子、长者、预算、饮食限制同时存在。
2. 在 Agent 对话框描述需求，按需选“文旅需求规划”。新安装不含预置可用模型；评委自接 API。视频没有现场调用私人模型。
3. 展示三个本地 Skill：需求规划、服务协同、内容创意。各有独立 `SKILL.md`，不要把它们说成一个万能模型。
4. 打开工作台，明确点击载入虚构案例，展示字段核对、factId 证据、候选行程、路线拓扑和模块修改。
5. 人工确认后由服务协同整理接待清单；内容创意使用可预览的公开字段生成待编辑草稿。
6. 最后说明源码和部署交付、无模型时的离线兜底、真实联网数据尚待核验。

## 录制与审核

- 建议先用自己的话完整讲一遍，再按画面停顿剪辑；不要照着屏幕逐字念功能列表。
- 评审版桌面包应在干净 Windows 用户配置下打开；首次模型状态应为“未配置”。不要展示自己的模型 ID、API Key、浏览器资料、学校或个人路径。
- `submission-agent-empty.png` 和 `submission-skills.png` 来自评审隔离配置下的 V5 桌面冷启动。后续工作台画面是产品内置的虚构实训案例，不应剪辑成实时大模型生成。
- 如重新录真实模型操作，必须使用专门的演示账号和额度，并在提交前逐帧检查敏感信息。没有这一步，就保持离线演示的诚实口径。
- 最终视频从头听看一遍，检查字幕节奏、Skill 中文名称、开头是否自然、是否误称实时地图或真实联网核验。
