# 旅策协同 4.2.0 赛题符合性自审

依据仅为用户提供的“文旅智能辅助场景基于 AI Coding 或 OpenClaw 引擎规范”课题文本。本自审不是主办方评分细则、认证或验收结论；项目未声明使用网易 Codewave 或帝王蟹平台。

## 已覆盖

- 咨询：本地事实卡检索，显示来源、日期、状态、冲突与模拟标识；可选模型回答受 factId 引用白名单约束。
- 规划：游玩、餐饮、住宿和显式交通统一 schema v2；确定性校验覆盖价格、开放、容量、餐次、夜晚、饮食、无障碍、天气、步行和预算。
- 个性化：按明确兴趣、完整总价和步行约束给出可解释排序，不伪造转化概率。
- 自动组合：本地有界、稳定、去重候选生成；搜索截断和取消不伪装为最优或无解。
- 服务：通过方案与服务端 `taskHash + selectedPlanId + confirmationId` 绑定，可生成接待草稿和复核清单。
- 营销/产品：三类交付均带确认、方案、事实和模拟元数据；营销使用允许字段投影，产品区分事实、创意和未验证项。
- 专业实训：旅游管理、文化创意、数字媒体三份任务书和量规；另有架构、原创贡献、8 分钟演示和赛题映射。
- 平台：桌面、文旅 Agent 和离线 HTML 三种入口；用户自配模型；无畅捷通登录、旧心跳、旧更新、托管 auto 模型或远程 Skill 市场。

## 安全与运行边界

- 不自动联网核验，不联系商户，不预订、不付款、不上传、不发布。
- 演示资源全部为虚构且标记 `demo: true`。
- API Key 只从用户目录配置读取，不写入源码、任务、日志、截图或交付物；远程地址要求 HTTPS，本机回环可 HTTP。
- 模型不可用时，本地评估、咨询、候选组合、报告和固定模板仍可用。
- 任务变更使旧确认与交付资格失效；pending/rejected 只能导出诊断。

## 验证证据

- `npm test`：本地规则、状态、Agent、安全、品牌和构建同步测试。
- `npm run test:evaluation`：25 个固定离线模拟案例，7 类，每次生成 JSON/Markdown 报告。
- `npm run test:live-dry-run`：默认 0 次真实模型调用；仅显式 `--live` 且给定预算/请求上限才允许调用。
- `npm run test:browser`：隔离 Edge 执行 26 项检查，覆盖两个主场景、需求差异、中文表单、咨询、规划、失效、生成、注入防护、窄屏和零业务网络请求。
- `npm run build`、桌面检查、品牌审计和发布包审计用于最终交付门禁。
