# 旅策协同 4.2.0 文旅智能辅助方案

## 用户与价值

面向景区客服、酒店/餐饮/旅行服务岗位和文旅相关专业实训。系统把碎片化的游客条件与资源资料统一为有版本、可追溯、可计算的任务，避免咨询、规划、接待和内容生产各自复制事实口径。

## 业务闭环

```text
需求原文（可选模型整理）
  → schema v2 人工核对
  → 本地事实咨询与候选生成
  → 确定性规则评估
  → 选定通过方案
  → 服务端哈希确认
  → 接待 / 营销 / 产品草稿
  → Markdown / JSON 导出与人工复核
```

确定性层不依赖模型。模型只整理需求、在给定事实卡范围内回答，或对确认后的安全投影生成草稿；它不能改写资源事实或越过确认执行外部动作。

## 原创实现重点

schema v2 将事实、证据、交通边、住宿夜和能力三态从自由文本中分离；规则引擎输出结构化 issue 和价格完整性；生成器有界、可取消且所有输出进入同一核心；服务端确认防止旧页面状态和过期响应生成肯定式承诺；营销投影主动排除游客自由文本。

## 范围

当前支持单一目的地、1–7 天、人民币预算、一个同行团队、0–20 个候选和最多 100 条资源。资源只存内存并可用 JSON 导入导出。实时天气、地图、铁路、航班、库存、订位和发布均未接入；未来若接入，只能作为默认关闭、用户明确触发并记录来源日期的可选适配器。

## 验证口径

测试覆盖任务契约、迁移、事实时效、饮食/无障碍、容量、全部计价、显式交通、日覆盖、排序、状态失效、Agent 白名单、营销脱敏、生成上限、HTML 注入、离线网络和发布品牌。25 例固定评测只证明模拟条件下的可复现行为，不证明主办方验收、实时准确性、收入、转化率或满意度。
