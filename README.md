# 旅策协同 Travel.AI 4.2.0

面向景区、酒店、餐饮服务岗位及旅游管理、文化创意、数字媒体专业实训的文旅全场景智能辅助 Skill 系统。4.2.0 用同一份可追溯任务贯穿有据咨询、游玩旅居餐饮规划、服务接待、营销草稿和产品创意。

## 启动与关闭

- `旅策协同文旅Agent.vbs`：主要入口；提供服务端哈希确认和可选模型协同。
- `旅策协同桌面版.vbs`：完整桌面端；包含模型设置和三个 OpenClaw Skill。
- `旅策协同-离线体验.cmd` 或 `tourism/旅策协同-双击体验.html`：零模型离线备用。

桌面窗口右上角关闭通常缩到托盘，彻底停止请从托盘选择“退出”。独立文旅 Agent 应点击其“退出”入口释放本机端口；测试不同版本前不要同时运行多个同源实例。

## 4.2.0 能力

- 两条参赛主流程：游客咨询与游住餐规划；基于确认方案的文旅营销与产品创意。页面首页可直接进入，不要求普通用户手写 JSON。
- 需求核对：自然语言先生成差异草稿，支持人数、预算、到离时段、过敏原与无障碍约束的局部更新；含糊指代先澄清，应用前不修改任务。
- 中文资料维护：可从空白创建景区/酒店/餐饮资源、首条事实卡和交通区间；取消不落数据，被引用记录不能删除。
- schema v2：任务 UUID/版本、逐日时段/餐次、住宿夜、结构化饮食与无障碍需求、事实卡、显式交通、独立住宿和候选方案。
- 确定性规则：证据时效、过敏原/交叉接触、无障碍三态、房型与时段容量、不同年龄门票次数、按人/房晚/固定价格、未知价格、开放/重叠、交通、步行、雨天和预算。
- 推荐语义：只在“通过已录入条件校验”的候选中比较；最低价排除总价不完整方案，轻松方案比较最大单日/总步行，体验方案比较明确兴趣覆盖。
- 咨询：本地关键词与字段加权检索最多 8 张事实卡；显示来源、日期、冲突与模拟标识；可选模型引用只允许本轮 factId。
- 自动组合：按逐日窗口、开放时间、服务时长和显式交通边排程，稳定去重并保留手工方案；截断列出原因，取消/迟到响应不覆盖当前任务，不伪装成最优或无解。
- 状态安全：服务端绑定 `taskHash + selectedPlanId + confirmationId`；预算、资源、事实、交通或方案变化后旧确认和交付资格失效。
- 三类交付：接待执行单、渠道化营销稿、产品创意卡均带确认/方案/事实/引擎/模拟/生成方式元数据；模型调用前可预览公开字段投影，事实正文和游客个人原文默认不外发；草稿可编辑并导出 Markdown、JSON 或打印/PDF。

内置“云水古城”及全部资源均为虚构实训数据。系统不接实时地图、天气、铁路、航班、票务、库存或商户系统；不会自动联系、预订、付款、上传或发布。

## 三个 OpenClaw Skill

- `travel-demand-planner`：需求整理、本地事实咨询、候选生成与确定性规划。
- `travel-service-coordinator`：当前确认方案的接待日程、核对清单和客服草稿。
- `travel-content-lab`：营销允许字段投影、可审内容和事实/创意分栏产品方案。

没有新增重复的第四个通用旅游 Agent。第三方候选 Skill 仅作 clean-room 设计参考，未复制或执行；审查记录在 `.development/plans/第三方Skill参考评估.md`。

## 模型与数据

模型设置支持 DeepSeek、Qwen、Kimi、OpenAI、Ollama、LM Studio 和自定义 OpenAI 兼容服务。配置位于 Windows 用户目录 `.tr-ai-assist/tr-ai-assist.json`，不进入项目或发布包。远程地址必须 HTTPS，本机回环可用 HTTP。

确定性评估、事实检索、候选组合和固定模板不需要模型。只有用户勾选并点击模型功能才会调用当前配置服务并产生用量。API Key 不进入页面、任务、trace、截图或导出。

## 构建与验证

```powershell
cd "<V4项目目录>"
npm run check:environment
npm run build:app
npm run start:app
npm run test:source
npm test
npm run test:evaluation
npm run test:live-dry-run
npm run test:browser
```

`build:app` 是参赛源码主链路，不读取桌面授权构建输入。`test:live-dry-run` 默认真实模型调用为 0；只有显式传入 `--live --budget-tokens N --max-requests N` 才可能调用，本次交付不运行 live 模式。`npm run package:contest` 生成 source、portable-web、offline-demo 三个 4.2.0 新包，并排除不可发布构建输入、个人配置、日志、浏览器 Profile、历史和绝对路径快捷方式。

## 材料与责任边界

- `tourism/training/`：三专业实训任务书和量规。
- `tourism/defense/`：架构、原创贡献、8 分钟演示和赛题映射。
- `tourism/赛题符合性审查.md`：基于用户提供赛题文本的诚实自审，不等同主办方验收。

派生桌面程序未签名，不冒充第三方签名或开发团队。底层运行时与第三方组件不宣称原创；当前结果只证明已录入资料和固定测试条件下的行为，真实数据与模型内容质量需另行授权验证。
