# JBGS-2026-06 参赛 PPT 与演示视频流程

适用作品：旅策协同 Travel.AI 4.2.0。建议 PPT 12 页，演示视频控制在 7 分 40 秒左右。整个材料使用同一条虚构业务故事，避免把视频录成零散功能清单。

## 一、统一演示故事

角色：某文旅目的地接待运营人员。地点：云水古城（虚构实训目的地）。

游客需求口径：

> 2 位成人、1 名儿童和 1 名长者，两日游，第一天下午 1 点抵达，预算 3500 元，喜欢非遗和亲子体验，有花生过敏，需要无障碍客房。

运营目标：先把自然语言需求转为可核对约束，再依据本地事实和资源生成游、住、餐方案；人工确认后生成接待执行单、渠道营销草稿和产品创意卡。

演示数据必须始终说明为虚构数据。不要展示学校名称、队员姓名、指导教师、校徽、学号、真实联系方式、API Key、浏览器账号、用户目录或终端历史。

## 三、7 分 40 秒演示视频分镜

### 0:00–0:20｜片头

画面：PPT 第 1 页。

旁白：

> 这是旅策协同 Travel.AI 4.2.0，参赛题目 JBGS-2026-06 文旅智能辅助场景。作品聚焦两个核心场景：游客咨询与游住餐规划，以及基于确认方案的营销和产品创意协同。

画面角落注明：“演示数据均为虚构”。

### 0:20–0:50｜一键部署与产品边界

操作：展示解压后的可携 Web 包，双击 `启动旅策协同参赛版.cmd`，等待浏览器自动打开。进入后停留在首页标题和黄色数据边界提示。

旁白：

> 可携版自带本机运行环境，Windows 解压后即可启动。核心评估、事实检索、候选生成和固定模板不依赖云端模型。系统不会自动联系商户、预订、付款、上传或发布。

评分证据：部署便捷性、异常情况下的离线可用性。

### 0:50–2:05｜场景一：自然语言需求核对

操作：

1. 点击“恢复模拟任务”，确认恢复虚构任务。
2. 点击“核心场景一 · 游客咨询与个性化行程”或滚动到“02 · 需求与方案规划”。
3. 粘贴统一演示需求。
4. 点击“本地整理草稿”。
5. 特写字段差异表，指出抵达时间、预算、花生过敏、无障碍客房等变化尚未写入任务。
6. 点击“应用所选草稿”。
7. 如需加强结构化展示，展开逐日时段、饮食与无障碍字段，点击“保存结构化约束”。

旁白：

> 系统不会让自然语言直接覆盖业务数据，而是先生成字段级差异。运营人员核对后再应用，未提及字段保持原值。过敏、无障碍客房和抵达时段都进入结构化约束，后续可以确定性验证。

评分证据：贴合前台接待需求确认流程、操作零门槛、减少误改。

### 2:05–2:45｜场景一：有据咨询

操作：滚动到“01 · 咨询问答”，资源选择“水乡家宴”或“亲子融合餐厅”；输入“是否支持花生排除和交叉接触控制？”，点击“检索本地事实”。特写事实卡的 factId、来源名称、采集日期、有效性、状态和“模拟”标识。

旁白：

> 咨询答案来自当前任务中的事实卡，并显示来源、日期、状态和模拟标识。资料未知、过期或冲突时，系统会提示核实，不会把模型推测写成确定事实。

评分证据：智能咨询应答、异常处理、数据可追溯。

### 2:45–3:55｜场景一：候选生成与确定性评估

操作：

1. 回到“02 · 需求与方案规划”。
2. 点击“生成并保留手工方案”。
3. 点击“确定性评估”。
4. 展示候选表的“结论、已知小计、总价完整、步行、问题”。
5. 指出最低费用、最少步行、兴趣匹配三种推荐口径；选择一条“通过”方案。

旁白：

> 规划器按照逐日窗口、开放时间、活动时长和显式交通边生成候选，并保留人工方案。费用、住宿容量、过敏原、餐次、无障碍、天气、步行和预算由确定性核心计算。未知价格不会被填成零，搜索达到上限也会明确说明截断，而不会冒充全局最优。

评分证据：个性化游玩旅居餐饮规划、功能实用性、异常处理。

### 3:55–5:05｜确认与接待执行单

操作：滚动到“03 · 服务接待”。

1. 点击“同步服务端评估”。
2. 确认方案 ID 正确。
3. 勾选“我已核对当前任务与选定方案”。
4. 点击“建立当前确认”。
5. 点击“服务接待材料”。不要勾选“使用已配置模型”。
6. 展示可编辑接待草稿中的团队、住宿、餐饮、交通、费用、待核实项和确认 ID。

旁白：

> 交付前必须经过人工核对。服务端用任务哈希、方案 ID 和确认 ID 绑定快照，避免需求变化后继续使用旧方案。即使没有模型，也能生成可执行、可追溯的固定接待模板。

评分证据：真实经营服务流程、操作安全、离线稳定。

### 5:05–6:25｜场景二：安全营销与产品创意

操作：滚动到“04 · 营销与产品”。

1. 设置渠道为“短视频”，受众为“亲子文化体验兴趣人群”，主题为“在地文化深度体验”，篇幅选“中等”。
2. 点击“预览公开字段”，特写投影不包含游客原文、饮食/无障碍自由文本和事实正文。
3. 点击“营销草稿”，展示短视频分镜结构；在输出框人工修改一句话，说明草稿可编辑。
4. 点击“产品创意”，展示事实、创意、依赖条件、最小试验和待验证项分栏。

旁白：

> 第二个场景复用已经确认的方案。模型调用前，运营人员可以查看公开字段投影；默认不外发游客原文和个人自由文本。营销输出会随渠道、受众、主题和篇幅改变结构，产品创意则明确区分已知事实、创意假设与待验证条件。所有材料都需要人工审核后再发布。

评分证据：营销创收增效、文创创新迭代、数据安全导出。

### 6:25–6:55｜异常与状态一致性

操作：回到方案规划，把预算从 3500 元改为 2500 元并保存或重新评估，再回到服务区，展示“旧确认和旧交付资格已失效”的提示。随后把预算恢复，避免最终画面停留在错误状态。

旁白：

> 任何预算、资源、事实、交通或方案变化都会立即使旧确认失效。在途请求也可以取消，迟到响应不能覆盖新任务，从流程上避免拿旧材料服务新需求。

评分证据：操作错误、任务变化和迟到响应处理。

### 6:55–7:20｜安全导出

操作：恢复并确认后，展示“导出 Markdown”“导出 JSON”“打印 / 另存 PDF”；只实际导出一个 Markdown，打开下载目录时不要暴露用户名路径。

旁白：

> 草稿可以继续人工编辑，并导出 Markdown、JSON或打印为 PDF。任务数据默认保存在页面内存，模型配置保存在用户目录，不进入源码和发布包。

评分证据：数据安全导出、文档完整性。

### 7:20–7:40｜工程证据与结束页

画面：PPT 第 11、12 页，显示三 Skill、三类交付包和测试结果。

旁白：

> 项目采用三个职责明确的 OpenClaw Skill、严格 schema 和本地确定性核心。本地回归 60 项、离线评测 25 项、浏览器交互 26 项全部通过，并提供源码、可携 Web、离线演示、一键部署和 API 文档。以上是固定环境验证结果，真实模型质量和经营效果仍需实际场景继续验证。

## 四、录制前的稳定性准备

1. 只使用最终时间戳为 `20260910-155957` 的可携 Web 包；不要在画面中展示旧时间戳中间包。
2. Windows 分辨率建议 1920×1080，显示缩放 100% 或 125%，浏览器缩放 90%–100%。
3. 关闭微信、邮件、系统通知、密码管理器提示和浏览器同步头像；桌面只保留演示目录。
4. 不在视频中打开模型设置。若必须展示，只展示“未配置/已配置”状态，不能显示或输入真实密钥。
5. 录制前完整走两遍操作；第三遍正式录制。需求文本放在无身份信息的临时记事本中便于粘贴。
6. 提前生成一份接待单和营销稿作为兜底截图，但正式视频仍应展示真实点击过程。
7. 每个按钮点击后停留 1–2 秒；重要字段使用鼠标框选或后期放大，不快速上下滚动。
8. 录完后逐帧检查：学校名称、队员信息、用户路径、通知、API Key、真实电话、真实商户、浏览器账号均不得出现。

## 五、现场或录制失败时的兜底顺序

| 问题 | 处理方式 | 旁白口径 |
|---|---|---|
| 浏览器未自动打开 | 复制终端显示的本机回环地址到浏览器 | 本机服务使用随机回环端口 |
| 模型未配置或网络异常 | 不勾选模型，继续本地整理、咨询、规划和固定模板 | 模型是可选增强，不影响核心业务闭环 |
| 候选因修改后全部待核实 | 点击“恢复模拟任务”，重新应用统一需求并生成 | 系统不会为了给出推荐而忽略硬约束 |
| 旧确认失效 | 重新同步评估、勾选核对并建立确认 | 这是预期的状态安全机制 |
| 页面误操作 | 恢复模拟任务；不要现场修改 JSON | 恢复的是虚构实训基线 |
| 服务需要退出 | 点击页面右上角“退出文旅 Agent”；页面丢失时在启动终端按 Ctrl+C | 退出后释放本机端口 |
